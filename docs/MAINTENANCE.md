# 仓库维护说明

## 本次整理

原有 75 个文件按用途归档。所有 ZIP 和展开快照内部结构不变；没有删除旧版或重复件。`file-map.json` 记录原路径、新路径、长度、Git blob 和 SHA-256，供核对和追溯。

移动后，默认分支上指向旧路径的外部链接需要更新；指定旧提交的链接仍可通过 Git 历史访问。原始验收中的本机绝对路径及历史文件引用保留原文，不代表整理后的目录。

## 后续上传约定

1. 单项目版本包分别放到对应 `packages`，名称保留项目、版本、日期与验收状态。
2. 展开的历史版本作为完整目录放到 `snapshots`，内部相对位置保持不变。
3. 组合备份放到 `bundles`，在包内分别列明每个子项目的版本。
4. 新增截图与验收 JSON 建议按版本和日期建子目录，并说明验证范围。
5. 每次发布更新项目 README 的入口；只有实际验收完成后才能修改“待验收”标签。

本仓库当前用于版本与证据归档。若后续需要持续开发，应另行提取经确认的源码为开发入口，再配置构建和检查，避免误把历史快照当成当前源码。
